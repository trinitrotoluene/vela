# Vela

![Deploy Status](https://img.shields.io/github/actions/workflow/status/trinitrotoluene/vela/deploy.yml?branch=master&style=flat-square)

This project is an event gateway wrapping the SpacetimeDB bindings to bitcraft. It maintains a redis cache and uses pub/sub to notify subscribers of cache changes.

## Exporting schema

```sh
dotnet run --project src/Vela.Gen -- generate-json-schema --outDir ./schema-output
```

## Regenerating the SpacetimeDB bindings

`src/Vela/Bindings` is generated by `spacetime generate` from the live module's schema. Never edit
it by hand: regenerate it whenever the game's schema changes (a row that no longer decodes fails
the whole subscription batch).

The CLI version must match the client SDK in `src/SpacetimeDB.ClientSDK` (`SDK_VERSION` in
`scripts/setup-sdk.sh`, 2.10.0). The SDK's cacheless patch (`patches/spacetimedb-cacheless.patch`)
changes only the SDK, not the generated code, so the bindings stay plain CLI output. Generate from
the schema the server reports, wrapped as a V10 `RawModuleDef`:

```sh
curl -s "https://bitcraft-release.spacetimedb.com/v1/database/idc-1/schema?version=10" \
  | jq '{V10: .}' > module-def.json
mkdir -p spacetimedb   # the CLI checks for a module directory even with --module-def
spacetime generate --lang csharp --module-def module-def.json --out-dir src/Vela/Bindings -y
```

`--module-def` is hidden from the CLI's help but works. `-y` lets it delete generated files for
tables and types the module no longer has.
